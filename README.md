# Liner Web Backend

Серверная часть веб-приложения **Liner** — музыкального стримингового сервиса.

Проект разрабатывается в рамках командного дипломного проекта.

## Технологический стек

- **Node.js 24** — среда выполнения JavaScript.
- **TypeScript 5** — язык программирования.
- **Fastify 5** — HTTP-фреймворк.
- **pnpm** — менеджер пакетов.

## Назначение проекта

Liner Web Backend отвечает за серверную часть веб-приложения и в дальнейшем будет взаимодействовать с основным Liner API.

Для HTTP-взаимодействия с основным API выбран Axios (интеграция ещё не реализована).

## Структура проекта

```text
src/
├── config/            # Конфигурация приложения
├── integrations/
│   └── liner/          # Интеграция с Liner API
├── modules/
│   └── health/
│       └── health.routes.ts
├── plugins/           # Плагины Fastify
├── shared/
│   └── errors/        # Общие ошибки
├── app.ts             # Создание приложения
└── server.ts          # Запуск HTTP-сервера

tests/
├── unit/              # Модульные тесты
└── integration/       # Интеграционные тесты

docs/                  # Документация
```

Часть директорий подготовлена для последующей разработки и пока не содержит реализации.

## Требования

- Node.js 24.x
- pnpm 12.x

## Установка

Клонировать репозиторий и установить зависимости:

```bash
git clone https://github.com/OleksiiMusienko/liner-web-backend.git
cd liner-web-backend
pnpm install
```

## Сборка и запуск

Проверка типов:

```bash
pnpm typecheck
```

Компиляция TypeScript:

```bash
pnpm build
```

Запуск сервера:

```bash
pnpm start
```

После запуска сервер доступен по адресу:

`http://127.0.0.1:3000`

## Health Check

Проверка работоспособности сервера:

```http
GET /health
```

Ожидаемый ответ (HTTP 200):

```json
{
  "status": "ok"
}
```

## Правила работы с Git

В проекте используется следующая стратегия ветвления:

- `main` — стабильная ветка.
- `develop` — основная ветка разработки.
- `feature/*` — ветки для отдельных задач.

Изменения в `develop` вносятся через Pull Request. Прямые изменения защищённых веток не используются в обычном процессе разработки.

Сообщения коммитов оформляются в стиле Conventional Commits.
