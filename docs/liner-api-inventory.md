# Liner Web — API Inventory

## 1. Призначення

Реєстр API для інтеграції Liner Web Frontend та Web Backend.
Статус "Документовано" означає, що маршрут описаний
у документації, але ще не перевірений HTTP-запитом.

## 4. Авторизація мікросервісів

- Запити виконуються з Web Backend.
- API-ключ зберігається лише на сервері.
- Обов'язковий заголовок: x-liner-user-id.
- Ліміти запитів необхідно враховувати.
- Адреси сервісів та API-ключі ще не отримані.

## 5. Основний Liner API

Попередня архітектурна домовленість: React Frontend
звертається до основного Liner API для автентифікації.

Наведені маршрути виявлено у вихідному коді Desktop.
Наявність маршруту в клієнті не підтверджує його
працездатність на актуальному сервері.

| Method | Endpoint                 | Параметри                              | Авторизація                    | Відповідь        |
| ------ | ------------------------ | -------------------------------------- | ------------------------------ | ---------------- |
| POST   | /v1/auth/login           | email, password                        | Без access token               | AuthTokens       |
| POST   | /v1/auth/register        | email, password, username, displayName | Без access token               | AuthTokens       |
| POST   | /v1/auth/refresh         | refreshToken                           | Без access token               | AuthTokens       |
| POST   | /v1/auth/logout          | refreshToken                           | Bearer access token            | Не уточнено      |
| GET    | /v1/me                   | —                                      | Bearer access token            | AuthUser         |
| GET    | /v1/search               | q, type                                | Вимоги сервера не підтверджені | SearchResponse   |
| POST   | /v1/tracks/{id}/playback | id                                     | Bearer access token            | LinerAudioStream |

Статус: підтверджено кодом Desktop, HTTP smoke-test
не виконано.

Додатково:

- /v1/search використовується Desktop як резервний
  пошук через основний API.
- Для отримання аудіо з R2 використовується
  /v1/tracks/{id}/playback.
- Авторизація та реєстрація користувачів Web
  заплановані через основний Liner API.
- Правила перевірки Web-сесії необхідно погодити.

## 7. Catalog Search — контракт

### Endpoint

GET /v1/catalog/search

### Query Parameters

| Параметр | Обов'язковий | Опис                                                      |
| -------- | ------------ | --------------------------------------------------------- |
| q        | Так          | Пошуковий запит, 1–300 символів, не лише пробіли          |
| type     | Ні           | all, track, artist, album, playlist. За замовчуванням all |

### Headers

- Authorization: Bearer API_KEY — обов'язковий.
- x-liner-user-id — обов'язковий.
- API-ключ не передається до браузера.

### Response

- HTTP 200 — JSON з масивом items.
- Кожен елемент має поле type: track, artist, album або playlist.

### Errors

| HTTP | Code                | Значення                         |
| ---- | ------------------- | -------------------------------- |
| 400  | USER_ID_REQUIRED    | Відсутній або некоректний userId |
| 400  | VALIDATION_ERROR    | Некоректні параметри             |
| 401  | INVALID_API_KEY     | Недійсний API-ключ               |
| 429  | RATE_LIMITED        | Перевищено ліміт                 |
| 503  | CATALOG_UNAVAILABLE | Каталог тимчасово недоступний    |
| 500  | INTERNAL_ERROR      | Внутрішня помилка                |

### Rate Limits

- 120 запитів на хвилину на користувача.
- 1200 запитів на хвилину на API-ключ.

### Verification

Статус: Документовано. HTTP smoke-test ще не виконано.

## 8. Lyrics Service — контракти

### Авторизація

Усі запити виконуються з Web Backend.

Обов'язкові заголовки:

- Authorization: Bearer API_KEY
- x-liner-user-id — стабільний ідентифікатор користувача.

Рекомендований заголовок:

- x-liner-client-ip — публічна IP-адреса користувача.

API-ключ не передається до браузера.
Спосіб перевірки користувача Web Backend ще не погоджено.

### 8.1. Resolve Lyrics

GET /v1/tracks/{id}/lyrics/resolve

Параметри:

- id — обов'язковий, YouTube video ID (11 символів)
  або SoundCloud ID формату sc:<число>.
- title — необов'язкова назва треку.
- artist — необов'язкове ім'я виконавця.
- durationMs — необов'язкова тривалість у мілісекундах,
  настійно рекомендована.
- duration — тривалість у секундах, якщо немає durationMs.

Якщо передані title та artist, сервіс не шукає
метадані треку самостійно.

Відповідь HTTP 200:

- trackId — ідентифікатор треку.
- cached — результат отримано з кешу чи ні.
- lyrics — об'єкт лірики:
  - format — формат тексту.
  - content — вміст тексту.
  - syncLevel — рівень синхронізації.
  - contentKind — тип синхронізованого вмісту.
  - matchedTrack — необов'язкові дані знайденого треку.

### 8.2. Lyrics Stream

GET /v1/tracks/{id}/lyrics

Параметри аналогічні Resolve Lyrics.

Формат відповіді: text/event-stream (SSE).

Події:

- metadata — інформація про трек, одна подія.
- lyrics — знайдена лірика, нуль або більше подій.
- done — завершення пошуку, одна подія.

Кожна наступна подія lyrics містить результат
не гірший за попередній.

Після done з'єднання закривається.
Якщо потік завершився без done, це помилка.

### 8.3. Lyrics Search

GET /v1/lyrics/search

Параметри:

- title — обов'язковий, до 300 символів.
- artist — обов'язковий, до 300 символів.
- durationMs — необов'язковий.

Відповідь HTTP 200:

- cached
- lyrics

Використовується, коли ID треку невідомий.

### 8.4. Формати лірики

| format   | Вміст                             |
| -------- | --------------------------------- |
| plain    | Звичайний текст                   |
| lrc      | Синхронізація за рядками          |
| ttml     | XML з часовими позначками         |
| qrc      | XML із синхронізацією за складами |
| richsync | JSON із синхронізацією за словами |

Рівні syncLevel:

- plain
- line_level
- word_level
- syllable_level

Мінімальна рекомендація: підтримати plain, lrc, ttml.

### 8.5. Errors

| HTTP | Code                | Значення                    |
| ---- | ------------------- | --------------------------- |
| 400  | USER_ID_REQUIRED    | Некоректний userId          |
| 400  | VALIDATION_ERROR    | Некоректний ID треку        |
| 400  | INVALID_QUERY       | Некоректний пошуковий запит |
| 401  | INVALID_API_KEY     | Недійсний API-ключ          |
| 404  | LYRICS_NOT_FOUND    | Текст не знайдено           |
| 404  | LYRICS_INSTRUMENTAL | Інструментальний трек       |
| 404  | ROUTE_NOT_FOUND     | Невідомий маршрут           |
| 429  | RATE_LIMITED        | Перевищено ліміт            |
| 500  | INTERNAL_ERROR      | Внутрішня помилка           |

Для 429 враховувати Retry-After.
Для діагностики використовувати x-request-id.

### 8.6. Rate Limits

- 30 нових треків на хвилину на користувача.
- 1000 нових треків на добу на користувача.
- 3000 нових треків на добу на мережу
  (за наявності x-liner-client-ip).
- 100 пошуків на годину на користувача.
- 1200 запитів на хвилину на API-ключ.

Ліміти нових треків стосуються Resolve та Stream.
Повторні запити того самого треку за добу
не витрачають повторно квоту нових треків.

### 8.7. Verification

Статус: Документовано.

HTTP smoke-test ще не виконано.
Реальні API URL та ключ доступу ще не отримано.

## 9. Catalog Service — сторінки каталогу

### Endpoints

| Method | Endpoint                   | Результат           |
| ------ | -------------------------- | ------------------- |
| GET    | /v1/catalog/artists/{id}   | Дані артиста        |
| GET    | /v1/catalog/albums/{id}    | Альбом із треками   |
| GET    | /v1/catalog/playlists/{id} | Плейлист із треками |
| GET    | /v1/catalog/tracks/{id}    | Дані треку          |

### Parameters

Усі маршрути мають обов'язковий параметр id у шляху.

Формати ID:

- Artist: YouTube UC... або sc_user_<число>.
- Album: MPREb_..., OLAK5uy_... або sc_playlist_<число>.
- Playlist: YouTube PL... або VL....
- Track: YouTube video ID (11 символів) або sc:<число>.

ID необхідно кодувати через encodeURIComponent.

### Authorization

Для всіх маршрутів обов'язкові:

- Authorization: Bearer API_KEY
- x-liner-user-id

Запити виконуються лише з Web Backend.

### Responses

Artist:

- type, id, name, verified, cover
- monthlyListeners, followers, bio
- tracks, albums, singles

Album:

- type, id, title, artists
- year, cover, trackCount, tracks

Playlist:

- type, id, title, author, description
- year, cover, trackCount, tracks

Track:

- id, title, artists, durationMs
- album, cover, explicit, audioVariant
- releaseDate, якщо відома

Невідомі значення можуть бути null або відсутніми.
Повні схеми відповідей доступні в /openapi.json.

### Errors

- 400 VALIDATION_ERROR — некоректний ID.
- 404 ARTIST_NOT_FOUND — артист не знайдений.
- 404 ALBUM_NOT_FOUND — альбом не знайдений.
- 404 PLAYLIST_NOT_FOUND — плейлист не знайдений.
- 404 TRACK_NOT_FOUND — трек не знайдений.
- 414 URI_TOO_LONG — занадто довгий ID.

Інші помилки та загальні ліміти описані
в розділі 7.

### Verification

Статус: Документовано.
HTTP smoke-test ще не виконано.

### 10.3. Presence

ТЗ передбачає:

- статус «Слухає зараз»;
- поточний трек і прогрес;
- останню активність;
- оновлення в реальному часі через gRPC.

Актуальний API Presence та Web-транспорт
не підтверджені.

Статус: потребує погодження з командою Liner.

### 10.4. Персональна статистика

ТЗ передбачає топ треків та виконавців
за останні 4 тижні й за весь час.

Доступність відповідних серверних маршрутів
окремо не підтверджена.

Статус: потребує перевірки.

## 11. Протоколи та події реального часу

### 11.1. Lyrics SSE

Endpoint: GET /v1/tracks/{id}/lyrics

Content-Type: text/event-stream

Послідовність подій:

| Подія    | Кількість    | Дані                                  |
| -------- | ------------ | ------------------------------------- |
| metadata | 1            | track: id, title, artists, durationMs |
| lyrics   | 0 або більше | trackId, lyrics                       |
| done     | 1            | trackId, found, cached, instrumental? |

Кожна наступна подія lyrics замінює попередню
кращою або рівноцінною версією.

Після done потік закривається.

Якщо з'єднання завершилося без done,
слід зберегти останню лірику або повторити запит.

Помилки 400, 401 і 429 повертаються як JSON
до початку SSE-потоку.

Квоти Lyrics описані в розділі 8.6.

Статус: документовано, HTTP-тест не виконано.

### 11.2. Presence

ТЗ передбачає сервіс на Go з двонаправленим
gRPC-стрімінгом.

Призначення:

- статус «Слухає зараз»;
- поточний трек і прогрес;
- спільне прослуховування;
- оновлення активності в реальному часі.

Для Web необхідно підтвердити:

- актуальний endpoint сервісу;
- Web-транспорт: WebSocket, SSE або gRPC-Web;
- спосіб авторизації;
- формат повідомлень;
- квоти та обмеження;
- правила приватності.

Транспорт для браузера ще не погоджено.
Пряме підключення через стандартний gRPC
не слід планувати без перевірки сумісності.

Статус: потребує погодження з командою Liner.

### 11.3. Verification

Lyrics SSE: протокол та події документовано.

Presence: актуальний транспорт, події та квоти
не підтверджені.

Реальні підключення ще не тестувалися.

## 12. Відповідність ТЗ та поточного API

### Статуси перевірки

- Підтверджено — знайдено контракт у документації
  або відповідний виклик у вихідному коді.
- Відсутнє — є підтвердження відсутності функції
  в дослідженій версії.
- Потребує погодження — поточна реалізація
  сервера або архітектурне рішення не підтверджені.

Підтвердження кодом Desktop або документацією
не означає успішного HTTP smoke-test.

| Бібліотека та плейлисти    | Методи Desktop є, актуальний сервер не перевірено                           | Потребує погодження         |

| Імпорт плейлистів          | Desktop імпортує локально; server-side таблиці видалені у 0016              | Потребує погодження         |
| Спільна PostgreSQL         | Передбачена ТЗ, доступ і операції не погоджені                              | Потребує погодження         |

### Виявлені розбіжності

1. Підписки та Leaderboards:
   Desktop містить методи API, але SQL-міграція
   0016 вказує, що серверних маршрутів не було.

2. Профілі:
   За Backlog v8.2 міграція 0017 видаляє
   bio та is_public. Відповідність ТЗ потребує
   погодження.

3. Плейлисти:
   За Backlog v8.2 міграція 0018 видаляє
   cover_url. Необхідно погодити механізм обкладинок.

4. Presence:
   ТЗ передбачає gRPC, але актуальний Web API
   та транспорт не підтверджені.

5. Імпорт:
   Desktop використовує локальний імпорт,
   а Web-сценарій ще необхідно визначити.

### Підсумок

Каталог і лірика мають документовані контракти.

Робота основних маршрутів потребує HTTP smoke-test.

Непідтверджені можливості не вважаються
реалізованими до перевірки актуального сервера
або погодження з командою Liner.
